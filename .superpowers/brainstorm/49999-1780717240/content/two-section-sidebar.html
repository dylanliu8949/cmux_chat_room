THE DECISION: what can a chat room @ ?
A · Room is bound to a group (1:1)
Each chat room owns an agent group. Selecting #feature-auth scopes @/@all to that group only (claude code 1, codex review). Worktree contexts stay isolated by construction — your original "don't let them interfere" goal. The bottom groups are the rooms' memberships.
C · Flat roster, groups are visual only
Any room can @ any agent; groups just tidy the list. @all would hit every agent across worktrees unless you hand-pick. Most flexible, but isolation is on you, and @all loses its "this room's agents" meaning.

(A hybrid is possible: bound by default, but you can still @ an agent from another group explicitly.)
