Channel layout: timeline vs threaded

How do fan-out replies (e.g. @all → 3 agents) get organized?

A

Timeline (Slack channel)

Strict time order. Replies marked "in reply to …". Simple, predictable scroll.

you → @all "review auth"
— you typed in claude tab (dropped) —
codex review ↳ re: review auth
3 issues found…
cursor 1 ↳ re: review auth
looks ok, 1 nit…
claude code 1 ↳ re: review auth
found a race…

Replies interleave by finish time; you scan the "re:" tags to regroup.

B

Threaded (grouped)

Each prompt is a parent; its replies nest under it. Fan-out stays grouped.

you → @all "review auth"
claude code 1 found a race…
codex review 3 issues found…
cursor 1 looks ok, 1 nit…
you → @claude-1 "fix the race"
claude code 1 fixed + test added…

Channel ordered by thread, not strictly by time. Great for fan-out/fan-in.

Trade-off: A is simpler to build & matches "Slack channel"; B groups parallel reviews beautifully but adds threading + forwarding-into-thread complexity.
